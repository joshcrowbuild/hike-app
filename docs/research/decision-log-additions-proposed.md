## 32. Stage 3 — Ingestion pipeline (build) ✅ *(June 23, 2026 — code: `ingestion/pipeline.py`, `ingestion/fetch/*`, `ingestion/conflate/match.py`)*
- **Pipeline shape:** ✅ a linear, idempotent **fetch → transform → hygiene → conflate → load** run, one CLI entry (`python -m ingestion.pipeline --region <id> [--dry-run] [--source ...]`). Region = a `regions/{id}.geojson` polygon carrying the `bbox` and `ingest_version`. *Why:* a monthly batch job, not a service (mirrors §8 "batch ingestion = scheduled jobs, not MCP"); `--dry-run` lets conflation be inspected before any Neo4j write.
- **Per-source fetchers, isolated:** ✅ OSM via Overpass (keyless, always attempted, the geometry **spine** per §27); NPS via public ArcGIS FeatureServer (keyless); USFS via **local bulk GeoJSON** (not a live call — see §34). Each fetcher returns a uniform `Feature(name, geom, source, ref)` and degrades to `[]` on non-200 so one source's outage never aborts the run. *Why:* keeps source authority tiers (§27) separable and honors degrade-and-disclose at ingest, not just at query time.
- **OSM segment consolidation precedes conflation:** ✅ OSM encodes a continuous trail as many disconnected `way` segments; running conflation on individual ~200 m fragments produced score=100 / overlap≈0.02 against full-length agency polylines. Fix = **merge all OSM ways sharing a normalized name** (`unary_union`) into one `Feature` before matching. *Why:* converts most spurious "review" cases to auto-accepts, collapses the "5× same trail in Scout results" UX bug, and cuts the total `CanonicalTrail` node count (pre-consolidation estimate ~2,899 → ~800–1,000 — see §33). 🔶 Grouping is by normalized name **within the bbox only**; cross-park name collisions ("Ridge Trail" in two units) are an accepted pilot-scale risk → add spatial clustering only if false-merges appear.
- **Idempotent writes:** ✅ all Neo4j writes are `MERGE`, keyed on synthetic IDs; safe to re-run monthly. `ingest_version = "{region}-{props.version}"` stamped on every `CanonicalTrail` / `SourceRecord` / `SAME_AS` (honors §28 versioning). *Why:* the monthly refresh must not duplicate nodes.
- **Collision-safe ID generation:** ✅ name-derived `canonical_id` / `sr_uid` slugs append a short content hash when the slug would truncate. *Why:* two `ref=None` trails sharing a 40-char name prefix would otherwise `MERGE` onto the same node and silently corrupt provenance — caught in self-review (§38), fixed before pilot.
- **Hygiene = drop-only-when-undisplayable:** ✅ a feature is skipped (`skipped_hygiene`) only when it has **no name AND no ref** (geometry-only, can't conflate or display); everything else loads. *Why:* §17 data-hygiene says validate-and-drop *malformed*, but a named-but-unmatched OSM trail is first-class (§3 graceful degradation) — load it as an OSM-primary canonical, don't discard breadth.

## 33. Conflation thresholds — tuned against the real run ✅ *(June 23, 2026 — review: `docs/research/conflation-review-2026-06.md`)*
- **First real conflation:** OSM (2,873 raw ways) × NPS (758) × USFS (459). Result before consolidation: 752 auto-accept / 466 review. Per-pair split (the load-bearing asymmetry):

  | Pair | Auto-accept | Review |
  |---|---|---|
  | OSM × NPS | 245 | 250 |
  | OSM × USFS | 507 | 216 |
  | **Total** | **752** | **466** |

  **~90% of "review" cases were not wrong matches — they were the OSM fragmentation artifact**, not a threshold problem; and the residue is overwhelmingly the **NPS pair** (250 of 466), while USFS already mostly auto-accepts. *Why it matters:* this is the empirical answer to the §23/§24 conflation spike — the meatiest Phase-0 unknown is **tractable** (§27's verdict holds), the lever is geometry repair (consolidation, §32), **not** loosening thresholds, and the per-pair split localizes the fragmentation cost (NPS's long polylines fragment worst against OSM ways).
- **Thresholds held, not loosened:** ✅ keep `name_auto=85`, `overlap_auto=0.5`, `hausdorff_auto_m=80`. *Why:* loosening geometry to absorb fragmented input would cause false merges between genuinely distinct features; fixing the input (consolidation) is correct and lossless. This resolves the §28 deferral ("conflation match-score thresholds tuned empirically — Stage 3").
- **Node-count figure clarified:** ✅ the `~2,899 → ~800–1,000` estimate in §32 is the **total** pre-consolidation `CanonicalTrail` count (OSM-primary **plus** NPS/USFS-primary canonicals), not the raw OSM way count (2,873). *Why:* the two numbers sit close enough to read as a typo; they are different denominators (raw fetched ways vs. minted canonical nodes).
- **Genuine review classes documented (the human-review residue per §27):**
  - **Road vs Trail same-feature** (OSM "Conway River Road" ↔ NPS "Conway River Trail", score 100): 🔶 auto-accept with NPS name winning, via post-conflation `road→trail` normalization — **NPS is authority tier 1 for official names** (§27, §28 best-view).
  - **Spur vs Main** (OSM "Humpback Rocks Trail" ↔ NPS "Humpback Rocks Spur Trail"): ✅ **do not auto-merge** — keep two `CanonicalTrail`s; the geometries are genuinely different features. *Why:* honors §28's "never auto-merge conflicting attrs — surface per-source."
  - **USFS ALL-CAPS truncation** ("LONG MOUNTAIN" ↔ "Long Mountain Trail"): ✅ `normalize_name()` lowercasing + suffix-stripping already catches most; 🔶 strip trailing ALL-CAPS suffix in the USFS fetcher for the rest.
- **Match provenance recorded:** ✅ `SAME_AS` edges carry `match_method` (`name+geom` / `name`) and `match_score`. *Why:* "which source said what, and how confidently we joined them" stays a traversal (§6, §28) — conflation decisions are themselves auditable.

## 39. Epic-driven development process + code hygiene ✅ *(June 23, 2026 — `docs/process/development-process.md`, `docs/epics/`, CLAUDE.md dev-standards)*
- **Three-layer work unit:** ✅ **Epic** (a capability deliverable) → **Story** (Given/When/Then) → **AC** (a pass/fail testable statement). Every AC gets ≥1 test, **written before the code** (TDD rhythm); tests named `test_s{story}_{ac}_{desc}`. Epics live in `docs/epics/epic-NNN-*.md` with a status flow `BACKLOG → DEFINED → IN_PROGRESS → REVIEW → DONE`. *Why:* the project's whole thesis is *evals for stochastic systems* (§1) — building against explicit, testable ACs is dogfooding that discipline, and makes "is this done?" objective rather than vibes. Epic 001 shipped **18 ACs / 23 tests** (tests exceed ACs by design — partial-failure and idempotency paths get their own coverage beyond the 1:1 AC mapping).
- **Targeted review replaces ultrareview for routine work:** ✅ after each epic, spawn a **narrow** self-review agent (only the changed files, specific rules to check — e.g. "owner_id on every new node," "source-or-silence holds"). Reserve full `/code-review ultra` for **Phase boundaries** or cross-cutting architectural changes. Every CRITICAL fixed before commit; MODERATE fixed or documented in the epic's DoD. *Why:* catch issues in the same session they're introduced, not 20 commits later; the broad review is expensive/slow and was crashing — match review cost to change scope. (This is the process that produced §38.)
- **Atomic commits + fail-loud code standards:** ✅ one logical change per commit (typical epic split: schema · core module · API wiring · tests · doc); imperative ≤72-char subjects with a *why* body; **never commit** `.env`, `data/`, commented-out code, debug `print()`, or `# TODO`/`# FIXME` (use the epic tracker). Code rule: **fail loudly at boundaries, degrade gracefully at the surface** — invalid input → `ValueError`; live-adapter failure → `None` (source-or-silence); never swallow an exception. `make check` (ruff + mypy + pytest) green before every commit. *Why:* clean history + a clear failure contract are what make the source-or-silence and access-control promises auditable (§17) — a swallowed exception is exactly how a wrong-but-unflagged fact reaches the user.
- **Build order is dependency-driven, recorded as epics:** ✅ next in flight — Epic 002 (Outcome-card endpoint → preference/stated-belief promotion) → Epic 003 (context assembly into `engine.plan()`, ≤500-char block, **no raw biometrics**, anonymous path unaffected — and the home of the §36 sub-floor *exclusion*) → Garmin poller → Valhalla drive time. *Why:* §22 phasing made concrete and trackable; Epic 003's "memory-on vs memory-off requires this to exist" is the bridge to the Stage-7 memory eval (§30).
